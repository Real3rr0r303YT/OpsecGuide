      Der vollständige Step-by-Step Guide für Operational Security & Privacy.
      Von der Hardware, die du bar im Laden kaufst, über ein gehärtetes Smartphone und eine
      Coreboot-Workstation bis zum isolierten Netzwerk-Stack. Keine Tracker. Keine Cookies.
      Keine externen Requests. Diese Seite ist eine einzige HTML-Datei.
    


    

      [DISCLAIMER] Dieser Guide dient der Privatsphäre, Selbstverteidigung und Bildung.
      Privatsphäre ist ein Grundrecht, kein Verbrechen. Firmware-Flashen und Bootloader-Unlocks
      können Hardware zerstören (Brick) und Garantien aufheben. Alles auf eigenes Risiko.
      Halte dich an die Gesetze deines Landes.

PHASE_00 // PREFLIGHT

    
Threat Model zuerst

    

      OpSec ist kein Produkt, sondern ein Prozess. Bevor du irgendetwas kaufst oder flasht,
      beantworte vier Fragen. Ohne Bedrohungsmodell baust du eine Festung mit offener Hintertür.
    

    

      
01 // Was schützen?
Identität, Standort, Kommunikation, Kontakte, Dateien, Finanzen.

      
02 // Vor wem?
Werbe-Tracker, Datenhändler, Stalker, Arbeitgeber, Kriminelle, staatliche Akteure.

      
03 // Wie wahrscheinlich?
Massenüberwachung trifft alle. Gezielte Angriffe sind seltener, aber teurer abzuwehren.

      
04 // Was kostet ein Leak?
Von nervig (Spam) bis existenziell (Doxxing, physische Gefahr). Danach richtet sich dein Aufwand.

    

    
Das schwächste Glied bist fast immer du selbst: Wiederverwendete Usernames, dieselbe Schreibweise, Login ohne VPN „nur dieses eine Mal“. Technik ersetzt keine Disziplin.

  


  
  

    
PHASE_01 // PHYSICAL OPSEC

    
Hardware-Anonymisierung

    

      Jedes Gerät hat eindeutige Kennungen (IMEI, Seriennummer, MAC-Adressen). Wer die Kaufkette
      kennt, kennt dich. Ziel: Zwischen deiner Identität und deiner Hardware existiert kein Datensatz.
    


    
    
      
  1. 
        
        
    
          
      
            
    • Keine EC-/Kreditkarte, kein PayPal, kein Online-Shop, keine Lieferadresse.
      • 
            
    • Keine Kundenkarte, kein Bonusprogramm, keinen Namen auf der Quittung, keine Garantie-Registrierung.
      • 
            
    • Für GrapheneOS: ein unterstütztes Pixel wählen (aktuelle Liste auf grapheneos.org/faq). Neuere Modelle bekommen länger Sicherheitsupdates.
      • 
            
    • Beim Kauf auf entsperrbaren Bootloader achten. Carrier-Varianten (z. B. manche US-Verizon-Geräte) sind oft gesperrt.
      • 
          
    
        
    
      
    2. 
      
  2. 
        
        
    
          
      
            
    • Nicht direkt am Wohn- oder Arbeitsort kaufen. Läden haben Kameras, das lässt sich nicht vermeiden, aber Distanz hilft.
      • 
            
    • Dein bestehendes Smartphone zuhause lassen oder ausschalten. Funkzellen-Logs verraten, wer wann im Laden war.
      • 
            
    • Bargeld vorher abheben, nicht am Automaten direkt neben dem Laden.
      • 
          
    
        
    
      
    3. 
      
  3. 
        
        
    
          
    Die beste anonyme Hardware ist wertlos, wenn du eine SIM mit deinem Namen einlegst: Der Provider verknüpft IMEI + IMSI sofort.
    
          
      
            
    • In vielen Ländern (inkl. Deutschland) ist SIM-Registrierung mit Ausweis Pflicht. Prüfe deine lokale Rechtslage.
      • 
            
    • Alternative: Gerät nur per WLAN (öffentlich / fremd) oder mit Daten-eSIM von Anbietern ohne KYC betreiben, wo legal.
      • 
            
    • Nie die alte SIM einlegen, auch nicht „nur kurz“. Einmal verknüpft, immer verknüpft.
      • 
          
    
        
    
      
    4. 
      
  4. 
        
        
    
          
      
            
    • Starkes Passwort/PIN statt Fingerabdruck (biometrische Daten können erzwungen werden).
      • 
            
    • Gerät nie unbeaufsichtigt lassen. Ausgeschaltet (BFU-State) ist es am sichersten.
      • 
            
    • Faraday-Bag für Situationen, in denen das Gerät garantiert stumm sein muss.
      •

PHASE_02 // MOBILE HARDENING

    
GrapheneOS flashen

    

      GrapheneOS ist ein auf Privatsphäre und Sicherheit gehärtetes Android ohne Google-Dienste,
      mit Exploit-Mitigations, Verified Boot und granularen Berechtigungen. Es läuft nur auf Pixel-Geräten,
      weil nur diese die nötigen Hardware-Sicherheitsfunktionen bieten.
    


    
    
      
  1. 
        
        
    
          
      
            
    • Stock-Android einmal starten, Google-Account-Login überspringen, mit WLAN verbinden (wird für OEM-Unlocking benötigt) und System-Updates einspielen.
      • 
            
    • Einstellungen → Über das Telefon → 7× auf „Build-Nummer“ tippen.
      • 
            
    • Einstellungen → System → Entwickleroptionen → OEM-Entsperrung aktivieren.
      • 
          
    
        
    
      
    2. 
      
  2. 
        
        
    
          
    Gerät ausschalten, dann Power + Leiser halten → Fastboot-Modus. Per USB mit dem Rechner verbinden.
    
          
    
            
    bash: fastboot
    

    # Android platform-tools aktuell halten (fastboot >= aktuelle Version)
$ fastboot devices
$ fastboot flashing unlock
# Am Gerät mit Lautstärke-Tasten bestätigen, mit Power auswählen.
# ACHTUNG: Das löscht alle Daten auf dem Gerät.
    
          
    
        
    
      
    3. 
      
  3. 
        
        
    
          
      
            
    • Empfohlen: Offizieller WebUSB-Installer unter grapheneos.org/install/web (Chromium-basierter Browser nötig).
      • 
            
    • Alternativ: CLI-Anleitung unter grapheneos.org/install/cli inkl. Signatur-Verifikation der Factory Images.
      • 
            
    • Nur von der offiziellen Domain laden. Keine Mirrors, keine „vorkonfigurierten“ Images von Dritten.
      • 
          
    
        
    
      
    4. 
      
  4. 
        
        
    
          
    Nur ein gesperrter Bootloader aktiviert Verified Boot vollständig. Ein offener Bootloader ist ein offenes Scheunentor für jeden mit physischem Zugriff.
    
          
    
            
    bash: fastboot
    

    $ fastboot flashing lock
# Am Gerät bestätigen. Danach in GrapheneOS booten.
# Anschließend: Entwickleroptionen → OEM-Entsperrung wieder DEAKTIVIEREN.
    
          
    
          
    Beim Boot erscheint ein gelber Hinweis „Your device is loading a different operating system“. Das ist normal. Prüfe den angezeigten Key-Fingerprint gegen die offizielle Liste und verifiziere die Installation mit der Auditor-App (Hardware-Attestation).
    
        
    
      
    5. 
      
  5. 
        
        
    
          
    GrapheneOS kommt ohne Google Play Services. Das ist der sicherste Zustand. Wenn du bestimmte Apps zwingend brauchst:
    
          
      
            
    • Separates Nutzerprofil oder Private Space anlegen (Einstellungen → System → Mehrere Nutzer).
      • 
            
    • Nur in diesem Profil Sandboxed Google Play über die GrapheneOS-App-Store-App installieren. Es läuft als normale App ohne Sonderrechte.
      • 
            
    • Kein Google-Account, wenn vermeidbar. Apps via Aurora Store (anonymer Login) im isolierten Profil beziehen.
      • 
            
    • Dein Haupt-/Owner-Profil bleibt komplett Google-frei. Profile teilen keine Daten.
      • 
          
    
        
    
      
    6. 
      
  6. 
        
        
    
          
      
            
    • Starke Passphrase (6+ Wörter oder 8+ zufällige Zeichen). Optional: PIN-Scrambling und Auto-Reboot (z. B. 8–18 h) aktivieren.
      • 
            
    • Network- und Sensors-Permission pro App entziehen, wo nicht benötigt. Storage Scopes / Contact Scopes statt Vollzugriff.
      • 
            
    • USB-C-Port auf „nur Laden“ wenn gesperrt (Standard in GrapheneOS).
      • 
            
    • Apps aus F-Droid / Accrescent bevorzugen. Messenger: Signal, Molly, SimpleX.
      • 
            
    • WLAN-MAC-Randomisierung pro Verbindung ist Standard. Bluetooth/NFC aus, wenn nicht benutzt.
      •

PHASE_03 // WORKSTATION HARDENING

    
ThinkPad & Coreboot

    

      Proprietäre BIOS/UEFI-Firmware ist eine Blackbox mit höchsten Rechten auf deinem System.
      Ältere ThinkPads lassen sich mit Coreboot (oder dem 100 % freien Ableger Libreboot)
      ausstatten. Darauf ein gehärtetes Linux. Ergebnis: Du kontrollierst den Stack vom ersten
      ausgeführten Byte an.
    


    
    
      
  1. 
        
        
    
          
    Gleiche Regeln wie Phase 1: bar bezahlen, Kleinanzeigen-Abholung, kein Versand an deine Adresse.
    
          
    
          
    
            
    ModellCoreboot/LibrebootHinweis
    
            
    X230 / T430Coreboot, LibrebootKlassiker, riesige Community. Externes Flashen nötig.
    
            
    T440p / W541Coreboot, LibrebootMehr Leistung, gut dokumentiert.
    
            
    X220 / T420Coreboot, LibrebootGünstig, alt, aber robust.
    
            
    X200 / T400LibrebootKomplett ohne Intel ME möglich, aber sehr alt.
    
          
    
          
    
          
    Die Support-Listen ändern sich. Immer aktuell prüfen: doc.coreboot.org und libreboot.org. Alternativ vorgeflashte Geräte von Händlern, die damit werben (dann aber keine anonyme Kaufkette).
    
        
    
      
    2. 
      
  2. 
        
        
    
          
      
            
    • CH341A-USB-Programmer (unbedingt die 3,3-V-Variante oder modden; 5 V kann den Chip grillen) oder ein Raspberry Pi mit SPI.
      • 
            
    • SOIC-8 / SOIC-16 Testclip (Pomona o. ä.), passend zum Flash-Chip deines Modells.
      • 
            
    • Ein zweiter Linux-Rechner mit flashrom.
      • 
            
    • Akku und CMOS-Batterie vor dem Flashen abklemmen.
      • 
          
    
        
    
      
    3. 
      
  3. 
        
        
    
          
    Ohne Backup kein Weg zurück. Lies den Chip mindestens zweimal und vergleiche die Hashes.
    
          
    
            
    bash: flashrom
    

    # Chip erkennen
$ sudo flashrom -p ch341a_spi
# Zweimal auslesen
$ sudo flashrom -p ch341a_spi -r backup1.bin
$ sudo flashrom -p ch341a_spi -r backup2.bin
# Hashes MÜSSEN identisch sein, sonst Clip neu ansetzen
$ sha256sum backup1.bin backup2.bin
    
          
    
          
    Backups offline an mehreren Orten speichern. Das Original-Image enthält gerätespezifische Daten (z. B. MAC-Adresse der Netzwerkkarte, Intel ME/GbE-Regionen).
    
        
    
      
    4. 
      
  4. 
        
        
    
          
      
            
    • Libreboot: fertige ROMs + Anleitung pro Modell. Coreboot: selbst bauen mit make menuconfig (Mainboard wählen, Payload z. B. SeaBIOS, GRUB oder edk2).
      • 
            
    • Intel ME mit me_cleaner neutralisieren (bei unterstützten Modellen; Libreboot erledigt das automatisch).
      • 
            
    • Für X230/T430 oft geteilter Chip (4 MB + 8 MB): Anleitung exakt befolgen.
      • 
          
    
          
    
            
    bash: flash
    

    # Beispiel: fertiges Image schreiben (Dateiname je nach Modell/Chip)
$ sudo flashrom -p ch341a_spi -w coreboot.rom
# flashrom verifiziert automatisch nach dem Schreiben ("VERIFIED")
    
          
    
          
    Falsches Image = Brick. Mit Backup und Programmer ist das reparierbar, ohne nicht. Erst Doku lesen, dann flashen.
    
        
    
      
    5. 
      
  5. 
        
        
    
          
    
          
    
            
    OSStärkeFür wen
    
            
    Qubes OSSecurity by Compartmentalization: jede Aufgabe in eigener Xen-VM, Whonix integriert, Wegwerf-VMs.Maximale Isolation. Braucht VT-x/VT-d und 16 GB+ RAM.
    
            
    Gentoo (hardened)Alles aus Source, Hardened-Profil, minimale Angriffsfläche, volle Kontrolle.Erfahrene User mit Zeit.
    
            
    Parrot OSDebian-Basis, Privacy- und Pentest-Tools vorinstalliert, AnonSurf.Einstieg, Security-Research.
    
            
    TailsAmnesisch, Live-USB, alles über Tor.Ergänzung für sensible Einzelsessions.
    
          
    
          
    
        
    
      
    6. 
      
  6. 
        
        
    
          
      
            
    • Full Disk Encryption (LUKS2, Argon2id) mit langer Passphrase.
      • 
            
    • Firewall standardmäßig auf deny incoming.
      • 
            
    • MAC-Randomisierung in NetworkManager aktivieren.
      • 
            
    • Webcam/Mikrofon physisch abdecken oder trennen. Bluetooth deaktivieren.
      • 
            
    • Regelmäßig updaten. Ungepatchte Software schlägt jede Firmware-Härtung.
      • 
          
    
          
    
            
    bash: hardening
    

    # Firewall (ufw)
$ sudo ufw default deny incoming
$ sudo ufw default allow outgoing
$ sudo ufw enable
# MAC-Randomisierung (NetworkManager)
$ sudo tee /etc/NetworkManager/conf.d/99-random-mac.conf <<'EOF'
[device]
wifi.scan-rand-mac-address=yes
[connection]
wifi.cloned-mac-address=random
ethernet.cloned-mac-address=random
EOF
$ sudo systemctl restart NetworkManager

PHASE_04 // NETWORK ISOLATION

    
Mullvad & Onion-Routing

    

      Dein ISP sieht jede Verbindung. Ein VPN verschiebt dieses Vertrauen zum VPN-Anbieter,
      Tor verteilt es auf drei unabhängige Relays. Kombiniert mit dem konsequenten Verzicht auf
      Big Tech schrumpft deine digitale Spur drastisch.
    


    
    
      
  1. 
        
        
    
          
      
            
    • Mullvad braucht keine E-Mail, keinen Namen, nur eine zufällige Kontonummer.
      • 
            
    • Bezahlung per Bargeld im Umschlag per Post oder Monero (XMR). Bitcoin ist pseudonym, nicht anonym.
      • 
            
    • No-Logs-Policy, RAM-only-Server und unabhängige Audits. Infos: mullvad.net.
      • 
            
    • Kontonummer offline notieren, nirgends in der Cloud speichern.
      • 
          
    
        
    
      
    2. 
      
  2. 
        
        
    
          
    
            
    bash: mullvad
    

    $ mullvad account login <KONTONUMMER>
$ mullvad lockdown-mode set on      # Kein Traffic ohne VPN
$ mullvad auto-connect set on
$ mullvad dns set default --block-ads --block-trackers --block-malware
$ mullvad connect
$ mullvad status
    
          
    
          
      
            
    • WireGuard nutzen, ggf. Multihop und DAITA (Schutz gegen Traffic-Analyse) aktivieren.
      • 
            
    • Auf GrapheneOS: Mullvad-App + Einstellungen → Netzwerk → VPN → Durchgehend aktiviertes VPN + Verbindungen ohne VPN blockieren.
      • 
            
    • Leak-Test unter mullvad.net/check.
      • 
          
    
        
    
      
    3. 
      
  3. 
        
        
    
          
    Nur von torproject.org laden und die Signatur prüfen. Auf Android: offizieller Tor Browser für Android.
    
          
    
            
    bash: gpg
    

    # Signing-Key des Tor Projects holen
$ gpg --auto-key-locate nodefault,wkd --locate-keys torbrowser@torproject.org
# Signatur prüfen ("Good signature" erwartet)
$ gpg --verify tor-browser-*.tar.xz.asc tor-browser-*.tar.xz
    
          
    
          
      
            
    • Security Level auf „Safest“ für sensible Sessions (deaktiviert JavaScript).
      • 
            
    • Fenstergröße nicht ändern (Letterboxing), keine Add-ons installieren: Beides macht dich fingerprintbar.
      • 
            
    • Nie mit echten Accounts einloggen. Tor-Identität und Klar-Identität strikt trennen.
      • 
            
    • Für systemweites Tor: Whonix (in Qubes integriert) statt selbstgebastelter Proxy-Configs.
      • 
          
    
        
    
      
    4. 
      
  4. 
        
        
    
          
    I2P ist ein eigenes, vollständig dezentrales Overlay-Netz (Garlic Routing), optimiert für Dienste innerhalb des Netzes (Eepsites, Torrents, Messaging). Kein Ersatz für Tor beim Surfen im Clearnet.
    
          
    
            
    bash: i2pd
    

    # Debian/Parrot
$ sudo apt install i2pd
$ sudo systemctl enable --now i2pd
# Web-Konsole: http://127.0.0.1:7070  |  HTTP-Proxy: 127.0.0.1:4444

PHASE_05 // RULES OF ENGAGEMENT

    
Die goldenen Regeln

    
    
      
  1. 
        
    Eine Identität = ein Gerät/Profil/VM, eigene Accounts, eigene Usernames, eigene Passwörter. Nie kreuzen.
    2. 
      
  2. 
        
    EXIF aus Fotos entfernen (z. B. exiftool -all= bild.jpg oder mat2). Zeitzonen, Schreibstil und Online-Zeiten verraten mehr als Inhalte.
    3. 
      
  3. 
        
    Diceware-Passphrasen, offline Passwort-Manager, FIDO2-Keys statt SMS-2FA.
    4. 
      
  4. 
        
    Die meisten Kompromittierungen nutzen bekannte, längst gepatchte Lücken.
    5. 
      
  5. 
        
    Erzähl niemandem von deinem Setup, deinen Accounts oder deinen Gewohnheiten. Das, was du nicht sagst, kann nicht geleakt werden.
